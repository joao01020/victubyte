# Contributing to VICTUBYTE

Thank you for your interest in contributing to VICTUBYTE!

VICTUBYTE is a 2D game that combines programming, logic, cybersecurity,
exploration and interactive storytelling.

We welcome contributions that help improve the gameplay, educational experience,
accessibility, performance and overall quality of the project.

## Getting Started

Before contributing:

1. Fork the repository.
2. Clone your fork.
3. Install Godot 4 with a compatible version for the project.
4. Open the project using `project.godot`.
5. Test the project before making changes.

Repository: https://github.com/joao01020/victubyte

## How to Contribute

You can contribute by:

- Reporting bugs.
- Suggesting new features.
- Improving gameplay mechanics.
- Improving the user interface.
- Fixing performance issues.
- Improving documentation.
- Creating or improving educational challenges.
- Improving accessibility and user experience.

## Development Guidelines

Please follow these conventions:

### Code

- Use English for all technical identifiers.
- Use descriptive variable, function, class and file names.
- Keep code organized and modular.
- Avoid unnecessary dependencies.
- Follow existing project architecture and conventions.
- Do not introduce real-world harmful hacking functionality.

### Game Development

- Preserve the established pixel-art visual direction.
- Test gameplay mechanics before submitting changes.
- Avoid breaking existing scenes, resources or interactions.
- Keep educational challenges fictional and isolated.

### Assets

- Only submit assets that you created or are authorized to redistribute.
- Include attribution when required by the asset license.
- Do not submit copyrighted third-party material without permission.

## Branching

Use descriptive branch names:

- `feature/feature-name`
- `fix/bug-description`
- `docs/documentation-update`
- `refactor/system-name`

Avoid committing directly to the main branch when contributing through a fork.

## Pull Requests

When submitting a Pull Request:

1. Explain what you changed.
2. Describe why the change is useful.
3. Include screenshots or videos when relevant.
4. Mention any related issues.
5. Confirm that the project runs correctly.
6. Clearly identify incomplete or experimental functionality.

Keep Pull Requests focused on a specific improvement whenever possible.

## Reporting Bugs

Use GitHub Issues and include:

- A clear description of the problem.
- Steps to reproduce it.
- Expected behavior.
- Actual behavior.
- Godot version and operating system.
- Screenshots or logs when available.
